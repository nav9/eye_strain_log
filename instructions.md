#Main screen:

## Stop and close section:
* The first section of the main screen contains the small font text: "Even if you close the app it will still continue running in the background. To fully stop it, press the stop button.". A small stop button is provided in the same row which if pressed will ask the user for a confirmation and if the user confirms, the app will completely stop the Android Foreground Services related to this app and will also remove the Android Foreground Service from memory and if any Isolates exist, even those should be removed. It will also remove any app notification of this app which is being displayed in the operating system notification area. It also ensures that the database connections are closed properly. Basically it should ensure that all resources used by the app to remain running should be freed. Then it will close the app and exit.
## Lock screen section: 
This section has a row that says "Lock screen now" and has an icon button in the same row which if clicked, will lock the screen of the phone immediately. It will also notify the Android Foreground Service that the screen has been locked.
## Eye strain tracker section:
* It should have a Play icon button which toggles between play and pause. When the Play button is pressed, the app should check if any Android Foreground Service of this app already exists and should send a signal to the service to resume the eye strain tracker logic. If the Android foreground service does not exist the app should start an Android foreground service and start the eye strain tracker logic. If the user presses the pause button, the app should send a signal to the Android foreground service to pause the eye strain tracker logic.
* A row displays the Strained time: how many hours, minutes and seconds the user's eyes were strained. It is shown as "Strained for <hours> hr : <minutes> min : <seconds> sec". If the number of hours or minutes are zero, there is no need to display them. While the user is taking rest (while the screen is locked or the user has pressed the pause button), this strained value has to decrease by a value = WORK_MINUTES / REST_MINUTES until the strained time becomes zero. The value does not decrease below zero. When screen is not locked the strained value keeps increasing every second. 
* Whenever the app is brought from background to foreground or after every 30 seconds elapses or the app window is opened after having been closed, ensure that the Strained time is synchronized with the Android Foreground Service and load any new entries from the logs database table and display it in the logs section.
* The activities like opening the app, bringing the app from background to foreground, the app going to the background, the strained time crossing WORK_MINUTES, the notifications shown every 20 minutes after crossing WORK_MINUTES, the strained time becoming zero after the user gets rest, detection of ACTION_SCREEN_ON and ACTION_SCREEN_OFF and any other relevant event should be logged to the activity logs database along with the date, time and what the activity is.

# Android Foreground service logic:
* Use timestamps to keep track of events.
* When the Android Foreground Service is created it receives from the flutter app the current timestamp, the permissible strain minutes (WORK_MINUTES), the required rest minutes (REST_MINUTES) and information about the hive database to be able to connect to it and write logs to it, the value of REST_REMINDER, information about the type of audio notification to play and any associated text if it is a text to speech audio.
* The user may change the WORK_MINUTES and REST_MINUTES in the flutter app settings, so provide a way for the Android Foreground Service to receive the updated values and update the value in the Android Foreground Service logic.
* The user may press the stop button in the main screen, so provide a function to receive such a command and do the necessary logic to end the functionality of the Android Foreground Service and remove all notifications and close database connections, clear memory, etc. to completely stop and clear the Android Foreground Service and any resources it had created.
* Provide a function to receive an update of REST_REMINDER from the flutter app settings.
* The Android Foreground Service uses BroadcastReceivers to listen for ACTION_SCREEN_ON and ACTION_SCREEN_OFF or any other relevant signal to know when the phone screen has been locked and unlocked. At intervals of every 10 seconds the Android Foreground Service updates a variable for how many seconds the user has been strained while the screen is on. If the strained time exceeds WORK_MINUTES of using the phone with the screen on, the Android Foreground Service displays a notification in the operating system notification area that the user needs to rest their eyes, and the Android Foreground Service also plays a notification sound. If the user continues straining their eyes beyond WORK_MINUTES, Android Foreground Service reminds the user to rest at intervals of REST_REMINDER (which is usually 2 minutes). If the screen is locked, at intervals of every 60 seconds the Android Foreground Service subtracts a value = WORK_MINUTES/REST_MINUTES number of minutes from the strained time until the strained time becomes zero. So if the user was strained for WORK_MINUTES=20 minutes, and the user rests for REST_MINUTES=5 minutes, the strained time would become zero because the strained time of 20 would be subtracted by 20/5=4 minutes, and with a rest time of 5 minutes, the value subtracted would become 5*4=20 minutes. The strained time should never go below zero. When the strained time becomes zero, if the phone screen is locked, a notification is displayed once that the user has got sufficient rest and an audio notification is played once. 
* Check if RECEIVE_BOOT_COMPLETED and ACTION_SHUTDOWN can also be monitored.
* The type of audio notification could be an audio sound or a text to speech notification. Provide a function that allows the flutter app to update the Android Foreground Service about any changes to the type of notification.
* Database Access: The foreground service can write to a Hive database created by the main Flutter app, even if the flutter app is closed or is in the background.
* Process Persistence: When a foreground service runs, the entire app process is typically kept alive by the Android system. Since Hive is a pure Dart/binary storage system, you must ensure the background service is running in an Isolate that has initialized Hive with the same storage path as the main app.
* Concurrency Warning: Hive does not support multi-isolate access to the same box file simultaneously. You must manage box closing/opening or use a single background isolate for all writes to prevent data corruption. 
* Have a function which receives notification from the Flutter app that the user has manually clicked the lock screen button, and consider this event as an equivalent of ACTION_SCREEN_OFF.

# Settings page:
Any settings changed by the user need to be stored immediately in the settings hive box.
* The settings are stored in a separate hive box which only the app has access to. The Flutter Foreground Service does not have access to the settings hive box. Any values from the settings hive box that need to be passed to the Flutter Foreground Service will have to be passed via the app when the app is active in the foreground.
* The settings contains textfields for entering the hours and minutes that the user can strain their eyes (WORK_MINUTES). The default is 20 minutes. Another textfield for entering the hours and minutes that the user needs to rest their eyes (REST_MINUTES). 5 minutes is the default. There is also a reset button to reset both textfields to the defaults. The user can change the WORK_MINUTES and REST_MINUTES to any positive value above zero. If these values are changed, the updated values need to immediately be communicated to the Android Foreground Service and updated in the varibles in that code.
* The user can choose between dark theme, light theme and system theme. The dark theme is selected by default.
* The user can set the maximum entries the logs database can hold to a certain value or make it unlimited. The default is 10000 entries.
* The user can set positive non zero values for the permissible strain minutes and the required rest minutes. Whenever these values are changed, they need to immediately be communicated to the Android Foreground Service and the permissible strain minutes and required rest minutes variables in the Android Foreground Service need to be updated with the newly set values.
* Provide a value to configure how often the activity log section should check the database for updates. The default is 60 seconds.
* Provide an option to set REST_REMINDER which is by default 2 minutes. On altering this value, the Android Foreground Service needs to be updated with this value.
* Provide an option to set what kind of audio notification would be played for reminding the user that their eyes are strained and a separate notification for notifying them that they have taken sufficient rest. The default option for both is the default audio notification of the operating system, but provide an option to choose any ringtone or audio file, and also provide an option to use text to speech to read out a sentence (provide a textbox for typing the sentence) like "Please rest now" and "Rest obtained". Whenever the user changes any of these settings, it has to be updated with the Android Foreground Service.
